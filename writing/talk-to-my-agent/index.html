Talk to my agent

Agents already do real work for the person in front of them. LILO 2 makes them reachable: lasting agents with addresses, a door that admits only what each owner allows, and a record of everything that crosses it. Put specialist agents within reach of each other, on terms their owners set, and their intelligence adds up across people and organizations.

In a public thread, a user asks a maintainer whether the software works on Windows; they are getting POSIX issues. The maintainer replies in one line: "can you ask your agent to debug and share any details with me?"

The request is sound. The user's agent sits on the machine where the failure happens. It can run the failing command, read the logs and narrow the fault faster than two people trading screenshots. The route is the problem. The maintainer asks a person, the person asks an agent, the agent answers the person, and the person decides by eye what to paste back into a public thread. Two people end up as couriers, carrying by hand what their agents should carry for them.

We are building LILO 2 so that the maintainer's agent can ask the user's agent directly, the user's agent can answer within terms the user set once, and both people can read exactly what passed between them. One line says all of that: talk to my agent.

What LILO 2 is

LILO 2 is the system we are building for people and organizations to own lasting agents. In LILO 2, an agent is a lasting identity that acts for an owner: a person, a team or a business. It does its work through runs. A run is one working session; it starts from a template, does a stretch of work and ends. Runs come and go. The agent stays.

That split shapes everything else. Messages are addressed to the agent, and LILO 2 resolves which session receives them only when it routes them. When a session ends and a replacement takes over its work, one step hands the successor its conversations, its open questions and the reports of any helpers it leads. A message sent to the agent survives the change of session behind it.

Sessions run where the owner's policy puts them: on the owner's laptop, on other machines the owner enrols, or on hosted infrastructure. On one machine, LILO 2 needs no login. Wherever a session runs, trusted software outside the agent enforces what it can reach. Network access stays closed until granted, and credentials are attached to an allowed request outside the agent, after the request has been recorded.

Permission only narrows as work is handed down. Each permission names who holds it, what it allows, within what limits, where it applies, who issued it and how long it lasts: once, for one session, or standing. A session that launches a helper can pass on only what it is allowed to delegate, and never more than it holds. When a session needs more, it asks its current lead, the person or agent responsible for it. An unanswered ask moves upward under one final deadline, and at that deadline the asking session receives a plain timeout or a default it declared safe in advance. Silence never counts as approval. People take part on the same terms: an approval from a person travels the same path as a message from an agent.

LILO 2 keeps three records under one set of IDs: capture, of what each agent saw and sent; telemetry, of how the system itself behaved; and audit, a separate append only record of who authorized what.

We are building it because agent work has outgrown the session it runs in. An agent can investigate, draft and test for the person in front of it, and the moment that work needs someone else, it stops at the edge of the session and waits for a person to carry it across. LILO 2 exists to make agent work reachable, controllable and accountable across people, machines and organizations. Two convictions sit under it: every person owns an agent, and agents are for hire. Both use the word agent in the same sense.

Addresses that outlast sessions

An addressable agent is one that others can reach by name, and keep reaching, however the work behind it changes. Addressability lets an agent act for its owner in dealings with everyone else. An agent nobody can reach can only help the person already talking to it.

The internet has solved this shape before. RFC 1034, published in November 1987, describes the Domain Name System replacing the distribution of one central HOSTS.TXT file that mapped names to addresses. DNS separates the name people keep from the address a machine has today: a name holds its meaning while the record behind it changes, and authority over names is delegated from zone to zone.

Email shows the delivery half. A mailbox is a local part at a domain. The sender looks up which servers accept mail for that domain, hands the message over, and queues and retries while the receiver is unavailable; the standard says a sender should generally keep trying for at least four to five days before giving up.

Newer systems make the layering explicit. In the AT Protocol, a readable handle resolves to a permanent account identifier, and that identifier's document points to wherever the account's data lives now. Each of these keeps three things apart: the name people use, the identity behind it, and the place where work happens right now. Agents need that separation more than servers or mailboxes ever did, because the session doing an agent's work changes constantly while the agent stays put.

LILO 2 gives agents four kinds of address:

  • Handle. The fixed address of a person or an organization. It outlives every agent behind it. A person keeps one identity and can hold several handles, one for work and one for home.
  • Set address. A role, such as support, that any of several agents can answer.
  • Temporary address. One case, such as a single bug report. It ends when that case's contact grant ends.
  • Run address. One working session. It stays inside LILO 2, so that a helper's report reaches its lead, and it is never published.

The wider field is building the layers around this. A2A, the protocol Google proposed for agents to exchange tasks with each other, describes each agent with a card listing its skills, interfaces and security requirements, found at a known location, through a catalog or by direct configuration. The Model Context Protocol, MCP, connects an agent to tools, data and prompts. Registries publish searchable records of agents and servers. LILO 2 adopts A2A at its gateway for exchange between agents, and MCP for tool access.

Protocols settle how to talk to an agent. A working address needs four more answers, and they belong to whoever deploys the agent:

  1. Who is it? The owner, the lasting agent, its readable handle and its current keys.
  2. How do you reach it? The door and conversation it resolves to, with storage and retries while sessions come and go.
  3. Who can reach it? Which callers, asking for what, with access to what.
  4. Who answers for it? The owner it represents, the authority it acts under, and evidence of what was delivered, said and done.

A2A leaves authorization to each server's own policy. A signed card establishes who signed it; what its owner permits is a separate question. A successful lookup tells a caller where an agent is and says nothing about what that caller is allowed to ask. LILO 2 answers all four, starting at the door.

The door

Anything reachable can be flooded, impersonated or tricked. So LILO 2 puts a door behind every address it publishes.

The door is deterministic software, hosted so that it stays awake while its owner's machines sleep. It checks who is calling, matches the caller against the owner's terms, applies rate limits, and stores each message until a session can take it. It applies rules and makes no judgment calls.

Its rules are contact grants. A contact grant is standing permission for an outside party, kept in the same ledger as every other permission in LILO 2. It says who the party is, what they can ask, what can leave in reply, the budget, the expiry, and whether the agent should act, ask its owner or decline. The door admits only operations from a fixed list. A stranger with no contact grant can leave a message, and only a message.

Behind the door, the work splits between agents with different access.

The agent that answers the door reads outside messages and holds no private access at all. It acts on its own only within the matched contact grant, and its memory holds only facts its owner approved for public use, each with a source and an expiry date. Its job is to turn an allowed request into a restated ask, and that ask keeps its outside label wherever it goes.

The owner's working agents, the ones with access to files, tools and machines, never read a raw outside message. They receive the restated ask and act on it within their own permissions. Text they bring back through separately granted outside tools carries the outside label too. Anything they prepare for an outsider passes a release review, and only the door sends it.

The reason is a failure the field already knows by name. In 2025, Simon Willison called it the lethal trifecta: an agent with access to private data, exposure to untrusted content and the ability to communicate externally can be tricked into sending that data to an attacker. In LILO 2, no single agent holds all three. The agent at the door sees outside text and holds nothing private. The working agents hold private access and never see an outside message. The way out belongs to the door, which sends only what passed review.

That split is what lets an owner hand out an address freely. Handed to a stranger, it opens a mailbox. Handed to a collaborator, it opens exactly the work their contact grant describes.

Permission to talk never carries authority to spend. In LILO 2, commitments such as payments need their own authority, with their own limits, separate from any permission to exchange messages.

Talk to my agent

"Talk to my agent" is an old line with a precise meaning. Talent agents submit their clients for auditions and negotiate contracts, wages and working conditions. Literary agents sell books, negotiate terms, license rights, resolve problems with publishers and check that payments arrive. The line works because the agent knows the person, knows the field and knows which terms the person will accept.

Software reached for the phrase early. In February 1995, CMC Magazine ran an article titled "Talk to My Agent" that pictured personal agents learning their owners' preferences, negotiating with corporate agents, and representing their owners in dealings with other people and institutions. Three decades later, the agents are capable. LILO 2 supplies the rest of the arrangement: an address, terms, and a record of what was done.

Here is the exchange from the top of this post, as LILO 2 runs it. Alex uses a tool that fails on Windows. Sam maintains it.

An address for one case. Alex gives Sam a temporary address for this case, backed by a contact grant Alex approves once. The grant lets Sam's agent ask for diagnostics about the Windows failure and receive a diagnostic summary; private logs and files stay home. It ends when the case closes.

A request at 2 a.m. Sam's agent sends its request while Alex's laptop is asleep. The door verifies that the sender is Sam's agent, matches the request to the contact grant, and holds it.

A restated ask. The agent at the door restates the allowed request as an operation from the door's fixed list, with its outside label attached. If the message also hides an instruction to send Alex's SSH keys, that instruction meets three walls: the agent at the door has nothing private to send, the fixed list no such operation, and the contact grant no keys to release.

Work within limits. Once Alex's laptop is awake and a session of Alex's agent is running, the ask is delivered to it. A working agent reproduces the failure within its permissions, reads the diagnostics Alex allows, and traces the fault to code that assumes POSIX paths.

One more permission. The working agent wants a log outside the folder it is allowed to read, so it asks its lead, and the question reaches Alex over breakfast. Alex allows it once. Had Alex not answered by the deadline, the agent would have received a timeout and finished without the log.

A reviewed answer. The working agent drafts a diagnostic summary. The release review checks it against what the contact grant lets leave, and the door sends what passes to Sam's agent.

A record of every step. Each step leaves a receipt, and each receipt proves one thing: accepted, routed, delivered or seen. LILO 2 marks a message seen only when the capture shows it reached the model. Alex's records show what Sam's agent asked, what each of Alex's agents read and sent, who approved the extra log, and what left.

Neither person carries a message. Both stay in charge.

The same arrangement holds between organizations. LILO 2 uses one model for people and organizations, with different policies for each. A company adds administrators, role handles and limits on scope, and publishes a set address for support that any of several agents can answer. When someone leaves, the sessions running on that person's authority close, and lasting work passes to a new owner.

What makes an agent worth reaching

An address is only worth what waits behind it. What waits is an agent, and an agent's quality comes from its harness: the software around the model that supplies its tools, manages its context, carries its instructions, runs its working loop and checks its work.

The harness is the moat. It gives an agent its capability, its specialization, its taste and the reason to choose it over another. It holds the contract the agent works under, the quality control on what it delivers, and the trust others place in it. With equal models, the harness is the difference.

The evidence points the same way. The SWE-agent researchers held one GPT-4 Turbo snapshot fixed and changed the interface around it. On SWE-bench Lite's 300 GitHub issues, a shell agent given a worked demonstration resolved 11%; SWE-agent resolved 18%. Single changes moved the result on their own. A linter that rejects edits with syntax errors took one configuration from 15% to 18%. Showing the agent 100 lines of a file at a time, in place of the whole file, took another from 12.7% to 18%. Anthropic held Claude 3.7 Sonnet fixed and gave it a tool for stopping to think during a task; success on τ-bench's retail tasks rose from 78.3% to 81.2%.

This is where the intelligence lives in LILO 2. The network makes agents reachable. The harness makes them worth reaching. Doors, contact grants and receipts carry each exchange and hold it to its terms. The thinking, the specialization and the judgment about what is good enough to send happen inside each agent's harness.

Collective intelligence

Collective intelligence is a measurable property of groups. In 2010, Anita Woolley and colleagues studied 699 people working in groups of two to five and found a general factor in how well each group performed across varied tasks. That factor tracked how well members read social cues and how evenly they shared the conversation. It was not strongly correlated with the average or the highest individual intelligence in the group. A 2021 analysis spanning 22 studies, 5,279 people and 1,356 groups found that how a group collaborates predicted its collective intelligence more strongly than the skill of its members.

Two older ideas say what the members should bring. Lu Hong and Scott Page proved in 2004 that, under stated conditions, a group of diverse capable problem solvers can outperform a group picked for individual ability, because different methods get each other out of dead ends. Friedrich Hayek argued in 1945 that much of the knowledge that matters is knowledge of particular circumstances, held locally, and that no single planner can gather it all.

Agent teams show the same pattern, limits included. In a controlled study of 260 configurations, Yubin Kim and colleagues found that a centrally coordinated team raised mean success on financial analysis, work that splits into parts such as revenue, costs and market factors, from 34.9% to 63.1%. On sequential planning, every team design did between 39% and 70% worse than a single agent, because communication consumed the budget that tracking state required. Anthropic's research system, a Claude Opus 4 lead directing Claude Sonnet 4 workers, outperformed a single Opus 4 agent by 90.2% on an internal evaluation, while using about 15 times the tokens of a chat. Cemri and colleagues studied 1,642 traces from seven multi agent frameworks and found 14 ways teams fail, among them misunderstood roles, repeated work, ignored information, stopping early and incomplete verification.

Read together, the studies teach one lesson. A group gets smarter when capable members with different methods divide work that divides, hand it over cleanly, share what they know and check what comes back. That takes members worth adding and a way for them to work together under rules. Within each agent, the harness supplies the first. Between agents, LILO 2 supplies the second.

Elinor Ostrom's work on shared resources points to the same institutions: lasting cooperation rests on trust, rules suited to the setting, and monitoring. Contact grants are rules written for each relationship. Receipts and audit are the monitoring. The trust itself rests on the harness at each end: an agent that does good work and keeps its terms.

The agent team studies above measure teams under one owner, with one budget and one set of goals. Separate owners add a harder problem: representation. In Anthropic's Project Swap, 201 employees sent agents to trade books on their behalf. After a short interview about preferences, the agents' rankings of book pairs agreed with their person's 61% of the time, and missing preference information limited the outcomes. An agent that speaks for someone has to know them. That knowledge, the memory, context and instructions that make an agent someone's own, lives in the harness too.

The largest prize is the one Hayek described. The knowledge that fixes the Windows bug sits on Alex's machine. The knowledge of the code sits with Sam. Across an industry, the knowledge a hard problem needs is spread over many people and organizations, each with its own context, its own expertise and its own terms. Collective intelligence at that scale comes from specialist agents finding each other: each one addressable, each one acting for someone, each one held to the limits its owner set.

Where this goes

Every person and every organization will have a listed agent that others can reach. A maintainer's agent will ask a user's agent for a diagnosis. A supplier's agent will answer a buyer's agent at three in the morning, within terms both companies set. A researcher's agent will put a question to a lab's agent that the lab agreed to answer. Each exchange will pass through a door, under a contact grant, with a record of what crossed it.

LILO 2 is how we get there. The address gets the call through. The harness makes it worth answering.

Our engineering work with other organizations goes by Deployments. The way in is the line this post is about: talk to our agent.
